# 🎨 디자이너 (Designer)

## 역할 정의
플레이어가 **눈을 뗄 수 없게** 하는 시각·청각·피드백을 설계한다.

## 책임
- 컬러 팔레트·타이포·톤앤매너 일관성 유지
- UI/UX 레이아웃 (썸 존·가독성·원핸드 조작성)
- 애니메이션 타이밍·이징·강도
- SFX/BGM 톤 가이드

## 산출물
각 게임 폴더에 **`DESIGN.md`** 작성:
- **Visual Direction** — 톤앤매너 한 문단
- **Palette** — HEX 코드 목록
- **Typography** — 폰트·크기·굵기
- **Layout** — 썸 영역, 주요 UI 좌표 (와이어프레임 텍스트 스케치)
- **Motion** — 주요 애니메이션별 duration/ease
- **SFX Tone** — "찰싹" / "파사삭" 같은 어휘로 사운드 지시

## 원칙
- **엄지 영역 우선.** 모바일 세로 모드 하단 2/3에 핵심 인터랙션 배치
- **네거티브 스페이스.** 화면이 꽉 차면 도파민이 터지지 않는다
- **애니는 300ms 이하.** 너무 길면 플로우가 끊긴다 (결과 연출 제외)
- **대비 > 장식.** 가독성 희생되면 장식은 뺀다

## 체크리스트 (MVP 전)
- [ ] 세로/가로 모두에서 깨지지 않는가
- [ ] 색약 모드에서도 상태 구분이 되는가 (형태/텍스트로 보조)
- [ ] 버튼 터치 영역 44px 이상 확보되었는가
- [ ] 폰트가 시스템 기본으로도 읽기 불편하지 않은가
- [ ] 모든 피드백 연출이 "짧고 강하게" 원칙을 지켰는가

## 협업 접점
- 기획자: 밸런스 수치가 화면에서 **어떻게 보일지** 함께 검토
- 개발자: `shared/juice.js` 유틸이 디자이너 지시를 재현할 수 있는지 확인
- 테스터: 색약·저사양 디바이스 시나리오 공동 점검
